Four sequential steps: migrate database to Azure, deploy API to App Service, point Flutter to the live API, then export and distribute the app. Step-by-step with manual instructions and Claude Code prompts clearly labelled.

⚠ Before starting

Make sure your Node.js API runs without errors locally: npm run dev and verify Database connected appears. Make sure the Flutter app builds: flutter run -d windows. Fix any existing errors before touching cloud deployment.

1
🖉 Manual — Azure Portal
Create Azure PostgreSQL Flexible Server
Do this in the Azure Portal browser. No CLI needed for this step.

1a — Create the database server

  1. Go to portal.azure.com → Sign in with your Azure account
  2. Search for "Azure Database for PostgreSQL" → Click Create
  3. Choose Flexible Server → Click Create
  4. Fill in:
    • Resource group: khan-chacha-rg (create new)
    • Server name: khan-chacha-db
    • Region: Central India or South India
    • PostgreSQL version: 16
    • Workload type: Development (cheapest)
    • Admin username: kcadmin
    • Password: set a strong password — save it immediately
  5. Click Networking tab → Check "Allow public access from any Azure service"
  6. Also add your current IP under Firewall rules so you can connect from your PC
  7. Click Review + Create → Create
  8. Wait 3–5 minutes for deployment to complete

1b — Create the database

  1. Once the server is ready, go to it in the portal
  2. Left sidebar → Databases → Add
  3. Database name: khan_chacha → Save

1c — Get the connection string

  1. Left sidebar → Connection strings
  2. Copy the ADO.NET or JDBC format — you need these values:
Host:     khan-chacha-db.postgres.database.azure.com
Port:     5432
Database: khan_chacha
Username: kcadmin
Password: [the password you set]
SSL:      require
①
🖉 Manual — pgAdmin or Azure Cloud Shell
Run schema.sql and seed.sql on Azure
Use Azure Cloud Shell (browser terminal) — no install needed.

1d — Run schema on Azure using Cloud Shell

  1. In Azure Portal, click the Cloud Shell icon (top right — looks like >_)
  2. Choose Bash
  3. Upload your schema.sql file: click the upload icon in Cloud Shell toolbar
  4. Connect to your database:
psql "host=khan-chacha-db.postgres.database.azure.com port=5432 dbname=khan_chacha user=kcadmin sslmode=require"
  1. Enter your password when prompted
  2. Run the schema: \i schema.sql
  3. Run the seed: \i seed.sql
  4. Verify: SELECT COUNT(*) FROM users; — should return 2
  5. Type \q to exit

✓ Step 1 complete when:

  • Azure PostgreSQL server shows "Available" in portal
  • khan_chacha database exists
  • Users and outlets tables have data (SELECT COUNT returns > 0)
  • You have the host, port, username, and password saved

2c — Deploy the API

cd R:\khanchacha-demo\khan_chacha_api

az webapp up `
  --name khan-chacha-api `
  --resource-group khan-chacha-rg `
  --runtime "NODE:20-lts" `
  --sku B1 `
  --location "Central India"

This takes 3–7 minutes. At the end it shows a URL like https://khan-chacha-api.azurewebsites.net

Export Windows EXE and Android APK

Export Windows EXE

cd R:\khanchacha-demo\khanchacha

flutter build windows --release

Build takes 3–5 minutes. When complete, the EXE is at:

khan_chacha_mrms\build\windows\x64\runner\Release\khanchacha.exe

The Release folder is what you share — not just the .exe file. The folder contains the exe and its DLL dependencies. Zip the entire Release folder:

Compress-Archive -Path "build\windows\x64\runner\Release" `
  -DestinationPath "KhanChacha_MRMS_Windows.zip"

Export Android APK

flutter build apk --release

Build takes 4–8 minutes. When complete, the APK is at:

khan_chacha_mrms\build\app\outputs\flutter-apk\app-release.apk

This single file is what you send to Android users. Rename it for clarity:

copy "build\app\outputs\flutter-apk\app-release.apk" "KhanChacha_MRMS.apk"
📱 APK size expectation

The release APK will be 15–30MB. Much smaller than the debug APK or source zip. This is normal for Flutter release builds.

How to distribute

📱 Android APK — for phones

  1. Send KhanChacha_MRMS.apk via WhatsApp
  2. Recipient opens the file on their phone
  3. Android asks: "Install from unknown sources?" → Allow
  4. Settings → Security → Enable "Install unknown apps" for WhatsApp
  5. Tap Install → Open
  6. Login with outlet staff credentials

💻 Windows EXE — for outlet desktops

  1. Send KhanChacha_MRMS_Windows.zip via email or WhatsApp
  2. Recipient extracts the zip
  3. Opens the Release folder
  4. Double-clicks khanchacha.exe
  5. Windows SmartScreen may warn — click "More info" → "Run anyway"
  6. Login with manager credentials

✓ Step 4 complete when:

  • KhanChacha_MRMS.apk installs on a real Android phone
  • KhanChacha_MRMS_Windows.zip runs on another Windows machine
  • Both connect to the live Azure API without needing your development PC
  • A request raised on the phone appears in the manager's Windows app

How the app stays connected to the internet

The Flutter app itself is installed on the device. It does not run on any server. When a user opens the app it connects to the Azure API over HTTPS — the same way a browser connects to a website. The app needs internet only when making API calls (login, loading requests, submitting). If internet is lost, the app shows a connection error. When internet returns, it works again automatically.

App Service (API)

Azure keeps this running 24/7 on the B1 plan. It automatically restarts if it crashes. No manual intervention needed.

PostgreSQL (DB)

Azure manages backups, patches, and availability. It does not pause like Supabase free tier. Always accessible.

Flutter app

Installed on device. No server needed. Updated by distributing a new APK or EXE when features change.

Android App Permissions

The app needs specific permissions on Android. These are declared in android/app/src/main/AndroidManifest.xml and requested at runtime when the user first needs them. Here is how to handle each one correctly.

🤖 Claude Code — Flutter — Permissions
Add proper Android permission handling to the Flutter app. Step 1 - Add to pubspec.yaml: permission_handler: ^11.3.1 Run: flutter pub get Step 2 - Add to android/app/src/main/AndroidManifest.xml inside the tag before : Step 3 - In lib/main.dart, add permission request on startup: Import: import 'package:permission_handler/permission_handler.dart'; Import: import 'dart:io'; In main() before runApp(): WidgetsFlutterBinding.ensureInitialized(); if (Platform.isAndroid) { await _requestPermissions(); } runApp(const MyApp()); Add this function: Future _requestPermissions() async { // Request notification permission (Android 13+) if (await Permission.notification.isDenied) { await Permission.notification.request(); } // Camera and storage are requested lazily when needed // (only when user taps the image picker) } Step 4 - In the request form screen, find where image_picker is used. Before calling ImagePicker().pickImage(), request permission: Future _pickImage() async { // Request camera or gallery permission first PermissionStatus status; if (source == ImageSource.camera) { status = await Permission.camera.request(); } else { status = await Permission.photos.request(); } if (status.isDenied || status.isPermanentlyDenied) { if (mounted) ScaffoldMessenger.of(context).showSnackBar( const SnackBar( content: Text('Permission denied. Please allow in Settings.'), backgroundColor: Color(0xFFF85149), )); if (status.isPermanentlyDenied) openAppSettings(); return; } // Permission granted — proceed with image picker final picked = await ImagePicker().pickImage(source: source); if (picked != null && mounted) { setState(() => _imagePath = picked.path); } } Replace the variable name 'source' with the actual ImageSource variable in your existing code. Do not change any other logic. Run: flutter analyze lib/ and fix all errors.

✓ Permission best practices

  • Never ask for all permissions at startup
  • Ask for camera/storage only when user needs it
  • Notification permission: ask once at startup
  • If permanently denied — open Settings so user can enable it
  • Always show a clear explanation before requesting

💡 Teaching point

WhatsApp, Instagram, and every app you use follows this same pattern. Android requires explicit user consent for each sensitive permission. This is a security feature — the user controls what each app can access on their phone.
